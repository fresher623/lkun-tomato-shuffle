# 番茄混淆 · 安卓 App 开发计划

日期：2026-09-10  
状态：2026-09-12 用户确认名称“番茄混淆”并启动开发。工程与内测实现见 README.md，验证进展见 docs/VERIFICATION.md。

## 1. 产品方向与默认假设

开发一款中文、离线运行的安卓图片工具，完成“选图 → 混淆／解混淆 → 预览 → 保存／分享”的完整流程。

本计划默认：

- 第一版优先尝试与参考网站双向互通；这是待验证目标，不是已确认能力。
- 先交付可安装的 APK 内测，再决定是否上架应用市场。
- 使用独立的 App 名称、图标和界面设计。
- 第一版免费、无账号、无广告、无云端图片存储。
- 暂定支持 Android 10 及以上；如果需要旧手机支持，在立项时调整范围。

## 2. 参考网站已确认的信息

网站说明使用 Gilbert 空间填充曲线，在浏览器本地进行可逆图片混淆，提供选图、混淆、解混淆、还原和下载；支持重复操作，下载格式为 JPEG。以上来自[参考网站公开页面](https://xiaofanqiehunxiao.com/)，本次未实测其处理结果，也未审查具体算法代码。

因此，应分别验证“功能类似”和“图片互通”。仅凭算法名称，无法确定后者。混淆也不应包装成密码加密产品。

## 3. 你需要准备什么

### 现在准备：启动开发所需

| 准备项 | 需要提供或决定的内容 | 暂时没有时的处理方式 |
| --- | --- | --- |
| 产品名称 | 已确定：番茄混淆 | 已完成 |
| 互通要求 | 是否必须解开参考网站生成的图片 | 暂按必须互通开展验证 |
| 目标用户和手机 | 自用、朋友内测或公开发布；常用手机型号 | 先以 Android 10+ 手机内测为目标 |
| 测试素材 | 建议 10～20 张可用于测试的照片、截图、长图、透明 PNG | 开发时可补充合成测试图 |
| 网站样本 | 同一张原图、网站混淆一次及两次后的原始下载文件 | 可在验证阶段用自有素材生成 |
| 界面偏好 | 主色、喜欢的风格，或允许开发方决定 | 默认简洁工具风格 |
| 发布与收费方向 | APK 内测还是准备上架；是否计划收费 | 先内测，收费后置 |

网站样本应保留原始文件、尺寸和操作次数，避免通过聊天软件压缩后再用作基准。

### 开发环境：开发方负责配置

- 一台开发电脑：建议 16 GB 内存及足够的 SDK、模拟器存储空间；主要用真机调试时可减少模拟器开销。
- Android Studio、Android SDK、Git，以及与所选构建工具匹配的 JDK。
- 至少一台安卓真机和数据线，开启开发者选项及 USB 调试；发布前补充其他品牌和低内存设备测试。
- 版本管理仓库、构建说明和测试素材目录。

你不需要提前购买服务器、域名、数据库或 AI API。本地像素处理不依赖这些服务。

### 准备发布时再补齐

- 正式名称、应用图标、介绍文案、宣传截图、支持邮箱。
- 固定的应用包名、版本规则及发布签名密钥；密钥和密码单独保管并备份，不提交进仓库。
- 根据实际数据处理行为编写隐私政策、用户说明及第三方组件许可说明。
- 若上架：确定渠道和发布主体，再核验该渠道届时的账号、备案、资质、隐私及目标 SDK 要求；审核时间不计入开发工期。
- 如果加入广告、统计、支付或联网服务，重新评估权限、隐私披露及开发范围。

## 4. 第一版功能范围

| 功能 | 第一版行为 | 验收重点 |
| --- | --- | --- |
| 选择图片 | 通过系统选择器导入单张 JPEG／PNG | 取消选择不会报错；异常文件有说明 |
| 图片预览 | 展示当前图片、尺寸及缩放查看 | 预览缩放不改变算法输入尺寸 |
| 混淆 | 每点一次执行一次正向变换 | 处理中防止重复任务并发 |
| 解混淆 | 每点一次执行一次逆向变换 | 可对应多次混淆逐次恢复 |
| 重置 | 回到本次导入时的图片状态 | 与“解混淆”含义明确区分 |
| 保存 | 默认 PNG，可选 JPEG | 导出新文件，保留原文件 |
| 分享 | 调用安卓系统分享面板 | 接收应用能够读取所分享文件 |
| 状态与错误 | 处理进度或忙碌状态、失败原因、取消 | 无卡死、无半成品保存成功提示 |
| 帮助与设置 | 格式说明、操作说明、离线说明 | 明确尺寸变化及有损压缩的影响 |

PNG 用于尽量保留处理后的像素；JPEG 用于减小体积，但有损编码不能承诺像素级还原。网站互通模式的导出细节以验证结果为准。

从外部导入的图片，其历史混淆次数通常未知。界面只记录本次会话的操作，不显示未经验证的“自动识别次数”或“还原成功”结论。

第一版不包含批量处理、视频／动图、多算法兼容、密码文件加密、会员、广告、云同步和自动识别混淆方式。后续按需求扩展。

## 5. 页面规划

采用一个处理主页和一个帮助／设置页，减少操作步骤。

处理主页：

1. 顶部展示应用名称和帮助入口。
2. 未选图时展示选择图片入口；选图后展示预览及图片尺寸。
3. 预览下方设置“混淆”“解混淆”两个主要按钮。
4. 辅助操作为“重置”“换图”，导出操作为“保存”“分享”。
5. 处理期间显示状态，完成后更新预览；保存失败时保留当前结果，允许重试。

帮助／设置页：导出格式、JPEG 质量、图片尺寸策略、使用说明、隐私说明及版本信息。

## 6. 技术方案

推荐 Kotlin 原生安卓开发，使用 Jetpack Compose 构建界面。当前目标仅为安卓，并且涉及图片内存、系统选图和文件导出，采用原生方案便于直接处理这些问题。[Compose 官方文档](https://developer.android.com/compose)

| 部分 | 拟采用方案 | 目的 |
| --- | --- | --- |
| 界面与状态 | Kotlin、Compose、ViewModel | 管理预览、忙碌状态和错误 |
| 图片处理 | 独立 Kotlin 算法模块、像素数组 | 正反变换可以独立验证 |
| 耗时任务 | Kotlin 协程，在后台调度计算 | 保持界面响应，支持取消 |
| 图片导入 | Android Photo Picker，不可用时回退系统文件选择 | 仅访问用户选择的图片 |
| 导出 | MediaStore 保存，临时内容 URI 用于分享 | 使用系统存储及分享机制 |
| 设置 | DataStore | 保存格式等轻量偏好 |
| 网络 | MVP 不引入联网 SDK，不声明 INTERNET 权限 | 核心流程完全本地运行 |

Android 官方的选图契约支持在 Photo Picker 不可用时回退至 ACTION_OPEN_DOCUMENT，适合兼顾不同设备环境；需特别测试无 Google 服务的目标手机。[Photo Picker 文档](https://developer.android.com/training/data-storage/shared/photo-picker)

在 Android 10 及以上，应用访问、修改自己创建的媒体文件不需要存储权限。结合系统选图器，第一版可以避免索取整个相册或所有文件的访问权限。[MediaStore 文档](https://developer.android.com/training/data-storage/shared/media)

不默认增加数据库、服务器或 C++ 层。若性能实测表明 Kotlin 算法达不到目标，再讨论进一步优化。

## 7. 首先验证：算法与网站互通

### 需要核对的细节

- 曲线遍历顺序、坐标方向、像素序列与二维图像的映射。
- 正向和逆向置换的定义，奇数尺寸及非正方形图片的处理。
- EXIF 方向、颜色空间、透明通道和编码行为。
- 输入尺寸限制、缩放规则和重复处理方式。

可研究公开的 Gilbert 实现作为算法参考，但不能假定网站使用完全相同的实现。采用代码前核对许可与署名要求。[Gilbert 项目](https://github.com/jakubcerveny/gilbert)

### 验证方法与通过条件

1. 制作带坐标或唯一像素值的小图，明确正向／逆向排列。
2. 对规范化的不透明 sRGB 像素输入，验证 App 内正反变换逐像素一致；再验证 PNG 保存、重新读取的完整流程。
3. 检查宽图、竖图、奇偶尺寸、小图和连续 1～3 次变换。
4. 执行网站混淆 → App 解混淆，以及 App 混淆 → 网站解混淆。
5. 将像素置换一致性与 JPEG 编解码误差分别记录，不把 JPEG 结果作为无损基准。
6. 对透明 PNG、EXIF 旋转照片及经过传输的图片单独形成兼容结论。

交付“样本 + 规则说明 + 对照结果”。如果无法确认互通规则，先标记兼容目标未通过，并说明差异；不静默改成仅 App 内互通后对外宣称兼容。

## 8. 大图、隐私与可靠性

- **内存：**800 万像素的单份四通道像素数据约为 32 MB，多份位图和映射数组会叠加占用。先读取尺寸并估算预算，限制同一时间处理一张图。
- **尺寸：**解混淆不能为了节省内存而静默缩小输入，否则可能破坏映射。超限时明确拒绝或提示采用其他设备；原图混淆前可提供用户可见的缩小选项。
- **生命周期：**处理旋转屏幕、切换后台、进程重建及取消任务；避免结果丢失后误报保存成功。
- **图片差异：**统一并记录方向及颜色处理策略；PNG 保真承诺限定到已验证的输入类型，透明通道单独测试。
- **临时文件：**仅为预览／分享保留必要缓存，提供清理策略；默认不建立含原图的历史图库。
- **分享：**提示接收平台可能改变图片。裁剪、缩放或截图后的图不承诺可恢复；尽量使用原文件传输。
- **离线验收：**使用本地图片，在飞行模式完成导入、处理与保存；若用户在系统选择器中选云端图片，其下载取决于系统媒体提供方。

## 9. 实施阶段与交付物

以下为熟悉安卓开发的单人工作量初估，以第一版范围稳定为前提，不是交付承诺。

| 阶段 | 预计工作量 | 可检查的交付物 |
| --- | --- | --- |
| 1. 需求与兼容验证 | 2～3 个工作日 | 需求定稿、互通样本与验证结论 |
| 2. 交互与项目基础 | 1～2 个工作日 | 页面原型、可安装的基础工程 |
| 3. 核心功能 | 3～5 个工作日 | 导入、处理、预览、保存、分享闭环 |
| 4. 真机验证与修复 | 2～3 个工作日 | 兼容性、内存、取消和文件异常测试记录 |
| 5. 内测交付 | 1～2 个工作日 | 签名 APK、源码、构建说明、使用说明、已知限制 |

合计约 9～15 个工作日。算法差异、增加旧系统支持、扩大机型范围和上架要求会影响排期；第 1 阶段结束后重新估算。

成本主要来自开发、设计和真机测试。离线 MVP 没有图片处理服务器的持续费用；商店、域名、宣传和商业化 SDK 的费用待渠道确定后另算。

## 10. 发布前验收清单

- [ ] 本地 JPEG／PNG 可导入，取消和不支持格式有合理处理。
- [ ] 核心算法在约定像素基准上正反完全互逆。
- [ ] 多次操作、奇数尺寸、宽高图、透明图和方向标签覆盖测试。
- [ ] 网站双向互通有对应样本和结果；不能确认的情况明确列出。
- [ ] 保存后重新导入仍能按约定恢复，JPEG 误差独立说明。
- [ ] 大图、内存不足、存储不足、处理取消和后台切换不导致无说明的失败。
- [ ] 原图不被覆盖，分享文件可读取，临时文件按策略清理。
- [ ] 飞行模式下本地完整流程可用，权限声明与实际行为一致。
- [ ] 在选定真机记录耗时及内存；以实测确定最终支持尺寸。
- [ ] 交付签名 APK、源码、构建说明，并完成签名密钥安全备份。

## 11. 建议的下一步

先确定网站互通是否为硬要求，并用成对样本完成算法验证。验证通过后再做页面原型和完整 App，可尽早确认项目最关键的技术条件。
