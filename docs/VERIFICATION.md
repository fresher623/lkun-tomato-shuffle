## 算法对照方法

从[参考网站](https://xiaofanqiehunxiao.com/)的 2026-09-12 页面提取两个无副作用的曲线函数，在隔离的 Node VM 中执行；未执行广告、统计或整站脚本。记录源码摘要于 `reference-capture.json`，生成 16 种尺寸的正向和逆向像素索引向量。

将 App 独立 Kotlin 实现与这些向量比较，全部一致。Kotlin 曲线实现改编自 [Gilbert BSD-2-Clause 项目](https://github.com/jakubcerveny/gilbert)，开源许可已写入源码目录和 App 帮助页。

本结果证明约定尺寸下的**像素置换规则一致**，不能扩大为整个网站和所有设备的完整兼容认证。网站每次操作重新压缩 JPEG，App 在导出时才编码；没有承诺 JPEG 字节或解码后的像素无损一致。

## 图片文件往返

本地安卓测试执行：生成不透明 PNG → App 导入／规范化 → 混淆 → PNG 编码写入文件 → App 重新导入 → 解混淆 → 与首次导入像素逐个比较，结果一致。

UI 测试覆盖真实后台处理完成、进度条退出、操作计数、Activity 重建和重置。该测试发现并验证修复了“处理结束清空进度后，延迟绘制回调仍读取空值”的崩溃。

## 待真机验证

当前 ADB 没有连接的设备，因此以下项目没有宣称通过：

- 系统 Photo Picker / 文件选择回退、不同厂商和云端图片提供方。
- MediaStore 图片保存后在厂商相册可见、存储不足及失败清理。
- FileProvider 分享 URI、接收应用读取、微信等应用的压缩行为。
- 真实网站 JPEG 下载文件与 App 的双向操作，尤其多次 JPEG 压缩后的画质。
- Android 10 最低版本、其他品牌／系统版本、低内存和大图性能。
- 相机 EXIF、广色域照片、半透明 PNG、损坏图片及进程被杀死等完整兼容矩阵。

本机 Windows 的 Robolectric 对文件描述符、Unix 路径规则和真实相册有平台差异。设备专属检查放在 `MediaStoreDeviceTest` 中，不用桌面替代实现冒充设备结果。

连接并授权手机后，从英文构建入口运行：

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest
```

设备测试会创建专用小测试图片，并在结束时删除自己创建的文件，不修改已有相册图片。人工测试可使用 `samples/` 中的原图、混淆一次和两次的 PNG；素材由网站向量生成，不经过聊天软件压缩。

## 内测限制

- 未保存的图片只保留在进程内；进程重建后需重新选择。
- 透明背景合成黑色，统一为 sRGB；PNG 无损仅指当前规范化像素。
- 超过本机像素／文件体积上限会拒绝，不静默改变待解混淆图片的尺寸。
- 当前 APK 保留调试及诊断依赖，体积尚未做正式发行优化。
- 正式发布签名、应用市场要求及全机型验收尚未完成。
