# l君の番茄混淆

离线安卓图片混淆工具，Kotlin + Jetpack Compose，Android 10 及以上。

沿 Gilbert 空间填充曲线重排像素，把图片打成看不出原貌的样子，再用反向操作还原。
处理全部在本机完成：不联网、不上传图片、不覆盖原图。

## 功能

**单张处理**

- 系统选图器导入 JPEG / PNG，不申请整个相册访问权限。
- 混淆、解混淆、重置到导入状态、清除当前图片。
- 「指定次数…」一次执行 1～100 次；连续同方向变换按等效位移一次算完，界面显示真实进度。
- 当前图片预览、双指放大与拖动、处理进度及取消。

**批量处理**

- 一次最多 **20 张**，每张处理 1 次，参数（方向、格式、质量）在任务开始时冻结。
- **处理不会写入相册**：结果先存在应用私有目录里，因此可以**边看边决定**。
- 每行显示处理后的结果缩略图，点「查看」全屏看细节（双指缩放）。
- 勾选需要的图片保存；也可以「全不选」后只保存某几张，或「全部保存」。
- 不满意的直接「移除」，只丢弃应用内的结果，**不动原图、不动相册**。
- 保存是"移动"：内容写入相册后删除应用内的副本，不会重复生成文件。
- 切到后台或息屏会继续处理，状态栏显示「正在处理 · 第 N / M 张」。
- 失败项可单独重试；存储不足或内存不足会停下并保留已完成的结果。

**导出**

- 默认 PNG 保存，可选 JPEG（质量 80～100），设置会保留。
- 保存到 `Pictures/TomatoShuffle`，系统分享，通过 FileProvider 授予临时读取权限。

**权限与隐私**

- **不声明 `INTERNET`**，应用无法联网，图片不会离开设备。
- 不加广告、统计、账号或云同步 SDK。
- 批量处理期间需要前台服务，因此声明 `FOREGROUND_SERVICE`、
  `FOREGROUND_SERVICE_DATA_SYNC` 与 `POST_NOTIFICATIONS`，用于显示处理进度。
  **拒绝通知权限也能正常处理**，只是看不到进度提示。
- 应用退出或被系统回收后，应用内未保存的处理结果会被清理；已保存到相册的图片不受影响。

## 构建

需要 JDK 21、Android SDK Platform 35、Build Tools 35.0.0。Gradle 8.11.1 已通过
Wrapper 固定，AGP 8.9.2、Kotlin 2.1.20。版本用于内测，不代表当前商店上架要求。

在 Android Studio 中打开本目录，配置 SDK 并同步即可。也可以在 PowerShell 执行：

```powershell
.\scripts\build.ps1 -JavaPath '你的 JDK 21 目录' -SdkPath '你的 Android SDK 目录'
```

脚本会依次运行核心测试、安卓本地测试、Lint、调试包与仪器测试包构建，并把 APK 复制到
`dist/`，同时打印 SHA-256。

单独运行：

```powershell
.\gradlew.bat :core:test
.\gradlew.bat :app:testDebugUnitTest
.\gradlew.bat :app:lintDebug :app:assembleDebug
.\gradlew.bat :app:connectedDebugAndroidTest   # 需要连接真机或模拟器
```

Windows 上中文路径会导致 Gradle 测试进程读取 UTF-8 参数文件时找不到测试类。构建脚本会自动
建立同级英文目录联接 `tomato-shuffle-build` 并从该入口构建；联接指向同一份文件，不复制源码。
如果项目路径已经是纯英文，脚本会直接构建，不创建联接。

## 算法互通的范围

以 2026-09-12 获取的参考网站规则为基准：沿 Gilbert 曲线，将像素循环移动
`round(((sqrt(5)-1)/2) × 像素数)` 个位置；解混淆执行反向映射。曲线中负数除法必须向下取整。

网站曲线函数产生的测试向量保存在 `core/src/test/resources/website-vectors.tsv`，来源摘要见
`docs/reference-capture.json`。**本应用不是该网站的官方客户端，也没有隶属或合作关系**；
网站源码快照仅放在本地忽略目录 `.research`，不打包进应用。曲线实现改编自 BSD-2-Clause 的
Gilbert 项目，许可与归属见 `THIRD_PARTY_NOTICES.md`。

像素置换兼容不代表 JPEG 编码逐字节一致。网站每次操作都会重新压缩 JPEG；本 App 处理期间保留
像素，导出时才编码一次。

## 内存与尺寸限制

单张图片的像素上限按**本机可用堆**动态计算，而不是固定值：

| 项目 | 规则 |
| --- | --- |
| 每像素开销 | 16 字节（源码位图 4 + 像素数组 4 + 路径数组 4 + 输出位图 4） |
| 预留余量 | 固定保留 48 MiB |
| 上限公式 | `min(800 万像素, (堆上限 − 单图页占用 − 48 MiB) / 16)` |
| 单边上限 | 4000 像素 |

在 256 MiB 堆的设备上实测：8 MP 图片处理中峰值约 91 MiB，编码期约 128 MiB。
**超过上限的图片会被明确拒绝，不会静默缩小**——缩小会破坏像素映射，导致之后无法准确还原。

图片文件的编码体积上限为 32 MiB，低内存设备会降低为最大堆内存的 1/16。

## 当前限制

- 单张静态 JPEG / PNG；导入后转为不透明 sRGB，透明通道合成黑底。
- 自动应用图片方向标签；外部图片若在处理后又被旋转、裁剪或缩放，不能保证解开。
- 屏幕旋转时任务与结果保留；进程被系统杀掉后重启为全新状态，未保存的应用内结果不恢复。
- 不识别外部图片是否已混淆、算法种类或历史次数；不自动判断"恢复成功"。
- 分享缓存超过 24 小时后会在下一次分享时清理；系统也可清理缓存。无账号或云同步。
- 应用内暂存的处理结果目前没有总量上限，长期不清空列表会占用应用私有空间。
- 云端相册图片首次读取需要下载，界面只显示"读取中"，没有单独的下载进度。
